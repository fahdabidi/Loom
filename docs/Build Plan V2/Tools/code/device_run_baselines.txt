# WARNING 1 — THE COMPOSITIONS ARE GONE, AND THAT IS NOT RECOVERABLE
# ---------------------------------------------------------------------------------------
# Every run below used `--mode targeted-precheck` with a scratch `--evidence-root`, which is
# CORRECT (that mode is `commitEligible: false` and writing to the canonical root destroys
# manifests for phases it never ran). The consequence is that no manifest was committed:
# `git show --stat` for e0536500, 28224656, b11a27c6 and 9deba3ed each touch ZERO files under
# `Evidence/`. The run logs lived in the VM's `/tmp`, which a reboot cleared; the VM has been
# up 4d5h and `/tmp` holds no b25 or precheck artifact.
#
# So for every figure below, the TOTAL survives and the PER-ROW COMPOSITION does not. Nobody
# can say which rows were in a bucket, only how many. The practical cost: `row_execution_failed`
# went 14 -> 10 across `9deba3ed`, and there is no way to tell whether the remaining 10 are a
# subset of the 14 or ten different rows with the first set fixed and new ones broken.
#
# An absence of committed manifests is NOT evidence that nothing failed. It is evidence that
# the run was correctly scratch-rooted and nobody wrote the result down.
#
# ---------------------------------------------------------------------------------------
# WARNING 2 — THE DENOMINATORS DIFFER BY RUN SCOPE, SO THE ROWS BELOW ARE NOT A TREND
# ---------------------------------------------------------------------------------------
# `b25Proven` is a PER-RUN RATIO over the workflows that run traversed, never a bar figure.
# Seven distinct denominators appear in the tickets: 0/0, 0/1, 0/3, 0/5, 0/7, 0/16, 1/82.
# They differ partly because reach improved and partly because the runs had different scopes
# — Garden-only versus Garden/Book, and different `--phases`. **Which, for each run, was never
# recorded.** So a figure falling between two rows cannot be read as a regression, and one
# rising cannot be read as a fix, without the scope that produced it.
#
# The clearest case: `workflows` went 8 (at 61a2e01b) to 4 (at c88b9b67), and those two runs
# are presented in a ticket as a before/after on `b25RowExecutionFailed` (6 -> 0). That may
# well be right. It cannot be CHECKED, because neither run's `--phases`/`--communities` was
# written down. Flagged as unverifiable, not as wrong.
#
