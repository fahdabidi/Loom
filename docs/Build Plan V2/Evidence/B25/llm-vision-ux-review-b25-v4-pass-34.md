### LLM-B25-VISION-034-001 - Action/detail screens still use low-contrast repeated utility shells
Severity: `major`

Pass 34 fixed the modal/dim overlay pattern and added tab evidence, but several action screens are still not visually production-grade: important content is washed out, the repeated panel structure feels like a generic task harness, and the UI does not yet read as purpose-built product surfaces.

Required fix: Create readable, domain-native action/detail surfaces for the affected workflows. Use opaque surface colors with accessible contrast, screen-specific layout, real domain objects and inputs, explicit primary/secondary/lifecycle actions, and visible result/receiver states; then full recapture B12-B20 evidence.

Affected rows: 22

### LLM-B25-VISION-034-002 - Workflow/persona product experience remains too generic on sixteen workflows
Severity: `major`

The current UI demonstrates improved content density but not yet full product experience depth for affected personas. Several workflows require a richer workflow-specific model rather than the same visual shell with different labels.

Required fix: For each blocking workflow/persona pair, implement a surface that makes the target persona real job obvious: object context, user inputs/decision data, primary action, alternative/change/reject/cancel path, result/receipt/history, and receiver/continuation state.

Affected rows: 22

### LLM-B25-VISION-034-003 - Six workflows still lack visible persistent result/lifecycle proof
Severity: `major`

These workflows can be opened and interacted with, but the screenshots do not yet prove the full semantic lifecycle a production user expects after the action.

Required fix: Add visible post-action result/receipt/status/history/receiver states to the affected workflows and recapture start/action/result rows proving those states.

Affected rows: 18
